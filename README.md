# 拂晓 活动地图规划器

把《拂晓：胜利之刻》活动地图建模成数据，然后点节点选路线，自动算出**带路条件是否走通、要打几场、油点在第几战后、一倍/三倍油耗和弹药消耗**。

> **非官方工具**：与《拂晓：胜利之刻》的开发方 / 发行方无关，纯粹是玩家自用的路线规划辅助，仅供个人参考。
> 游戏名称、阵营名、舰名、掉落信息及地图数据的一切权利归原权利方所有。
> 仓库里**不含**任何账号数据（舰灵库是空模板，见「数据怎么存」）。

## 怎么用

**双击 `index.html` 就能打开，不需要起服务器。**

（页面全部用经典 `<script>` 标签加载，就是为了绕开 Chrome 在 `file://` 下对 `fetch`/ES module 的 CORS 拦截。）

操作流程：

1. 在右侧「舰灵库」录入你手上的舰灵（舰名/油耗/舰种/国籍必填，航速和索敌可留空）
2. 切到「编队」，建编队、把舰灵填进两个队伍（列表第一个位置即旗舰）、指定哪一队是**强队**
3. 在左侧地图上从起点开始点节点，逐步延伸出你想走的路线（点错了用「撤回一步」）。
   节点的**判定范围就是「可去」时那个黄色虚线圈**（r=40），圈内随便点哪都算命中，不用精确戳到图标上
4. 右侧「路线汇总」给出战斗数、油点位置、一倍/三倍油耗、弹药占用、带路条件逐条判定
5. 下方「路线对比」列出所有 23 条路线，按油耗排序，点一行可直接载入到地图

## 数据怎么存

分三层：

- `data/*.js` —— 仓库里的**真实文件**，是初始数据。其中 `ships.js` / `fleets.js` 在仓库里是**空模板**（舰灵库人人不同，不适合进公共仓库）
- `local/*.local.js` —— 可选的**本机私有层**，不进 git：`app/main.js` 启动时会按需加载它，里面的 `FX_SHIPS` / `FX_FLEETS` 会覆盖掉空模板（文件不存在只留一条 404，不影响启动）。只是自己用、不在意提交内容的话，无视这一层即可（详见 `local/README.md`）
- `localStorage` —— 运行时的草稿，界面上的改动即时保存、刷新不丢

**文件层和草稿是按 id 合并的，不是二选一**：草稿里的改动优先（本机改过的以草稿为准），文件里新增的条目会补进来，本机删掉的用墓碑挡住、防止被文件里的旧数据"复活"。所以 `ships.js` 可以在外部批量重新生成，重新打开页面就能看到新船，不会覆盖掉你的本机编辑。

界面上改完，用「导出 ships.js / 导出 fleets.js」下载，覆盖回 `data/` 下的同名文件即可；
想让自己的舰灵库不进 git，就覆盖 `local/ships.local.js` / `local/fleets.local.js` 代替。
（页面是 `file://` 打开的，浏览器不允许网页直接写本地磁盘，导出再覆盖是唯一可靠的做法。）

如果浏览器禁用了本地存储，页面右上角会提示，此时务必用导出保存。

## 组队（舰灵多的时候怎么不迷路）

舰灵上百艘之后，"找不到想要的船"是主要痛点，所以：

- **选船面板**：点队伍里的「+ 添加舰灵」打开。按**舰名搜索**（`拉菲` 能同时命中 `拉菲(DD-459)` 和 `拉菲·改(DD-724)`）、按**舰种/国籍多选快筛**、可「只看收藏」。每行显示 油耗/航速 供决策。**已在另一个队伍的船会标灰并注明「已在 N 队」**，点不动
- **两队合并统计**：编队面板常驻显示合并后的 舰灵数 / 各舰种 / 各阵营 / 均速 / 索敌
- **带路条件实时对比**：把当前路线的条件拉过来逐条比对，并**算出差多少**（例如「舰队中 航母　需 3~12　当前 1　✗ 少 2」）。组队和判定在同一视野里，不用来回滚
- **收藏**：★ 收藏的船在列表和选船面板里永远置顶，并写进导出的 `data/ships.js`（可选字段 `fav`）
- **一键清空某一队**：每个队伍标题右边（`N/6` 旁边）有个「清空」，点一下只把**这一队**的舰灵全下，
  另一队和编队本身（名字、「强队」设置）都不动；这一队本来就是空的时候按钮是禁用的
- **舰灵库**：支持全库搜索 + 舰种/国籍筛选 + 按舰名/舰种/油耗/航速/最近使用排序

同一艘船**不能编入两个队伍**。这不只是游戏规则——重复编入会让"两队合并"的舰种/阵营计数重复，带路条件判定和油耗都会悄悄算错，所以增删都走 `FX.store`，由它守住这条不变量。

## 关键规则

### 图结构

有向图，**不存在双向边**（A→B 则 B 一定不能回到 A）。本图是无环的，但代码不依赖这个假设，枚举时带环检测，以后遇到"绕一圈回来"的活动地图也能处理。

节点类型：`start` 起点 / `battle` 战斗点 / `boss` BOSS点 / `supply` 补给点（油点）。

### 带路条件

条件都是**单谓词**，不存在"且"。求值基准是**两队合并**：

| 原文 | 含义 |
|---|---|
| `旗舰为 战列<2` | 两个旗舰中，舰种为战列的数量 < 2 |
| `舰队中 航母 数量<3` | 两队合并的航母总数 < 3 |
| `舰队中<奥鲁加>数量≥4` | 两队合并的奥鲁加籍总数 ≥ 4 |
| `舰队均速值<34` | 两队合并的均速 < 34 |
| `舰灵数量<10` | 两队合并的舰灵总数 < 10 |
| `舰队索敌值≥800` | 两队合并的索敌 ≥ 800 |

**两个换算假设**（都能在编队里手动覆盖，界面上填「舰队均速值 / 舰队索敌值」即可）：

- 均速值 = 全部舰灵航速的算术平均
- 索敌值 = 全部舰灵索敌值之和

只要有一个舰灵没录航速/索敌，这两个条件判为「未知」而不是「不满足」——避免把"缺数据"误报成"走不通"。

除了逐条判定，还会做**冲突检测**：条件是互斥分段的，如果一条路上同时要求 `航母<3` 和 `航母≥3`，求交集为空，页面会直接告诉你这条路物理上走不通。

### 油耗与弹药

- 每个战斗节点从两队里**任选一队**出战
- **每队每轮最多打 5 战**（出战一次消耗 1 弹药，上限 5），即全路线最多 10 战
- 油点返还「**上一个战斗节点的出战队伍**」的一半油，向下取整
- 三倍模式：只放大油耗和掉落，**不改变战斗场次、也不改弹药消耗**

```
F = 某一场出战队伍的全部舰灵油耗之和
一倍: 单战消耗 F      油点返还 ⌊F/2⌋      → 一轮净耗 = ΣF    − Σ⌊F/2⌋
三倍: 单战消耗 3F     油点返还 ⌊3F/2⌋     → 一轮净耗 = Σ3F   − Σ⌊3F/2⌋
```

注意三倍是**先乘三再取整**：F=55 时一倍返 27，三倍返 ⌊165/2⌋=82，而不是 27×3=81。
（返还基数取自油点**前面那一战**的出战队伍，所以队伍分配会同时影响消耗和返还，两者耦合。）

**自动分配**穷举 2^(战斗数) 种方案（最多 10 战 → 1024 种），在满足「BOSS 点必须强队」和「每队 ≤5 战」的前提下取所选模式油耗最小。

### BOSS 点与金色掉落

掉落列表第 0 槽是活动代币卡，之后是舰灵。舰灵头像**顶端横条颜色代表稀有度**（金 > 紫 > 蓝 > 绿），右上角绿色斜标是「掉落UP」。

- 金色掉落 = 顶端**金色横条**（不是"金发角色"，这点容易认错）
- 有的活动的 BOSS 会有两个金色掉落，其中可能一 UP 一非 UP；非 UP 的会稀释掉落池，数据的 `otherDropsGold` + `polluted` 字段就是记这个
- 普通战斗点也可能有金色非 UP 舰灵，自动化识别不了，页面给了手动「标记污染」按钮

以上「掉落UP / 非UP / 污染」都是**限时活动**才有的概念，档案（常驻）图上不适用，详见下一节。

## 限时活动与档案

同一张活动图在游戏里有两种存在形态，本工具在页面上按模式分开展示（开关在地图下拉右边、「一倍/三倍油耗」左边）：

| | 限时活动（首次 / 复刻 / 闪回） | 档案（常驻） |
|---|---|---|
| 活动代币商店 | 有 | **没有** |
| 金船掉落加成（掉落UP） | 有 | **没有** |
| 地图本身（节点、带路条件、装甲、金船掉落） | 完全一样 | 完全一样 |

- **首次活动、复刻、闪回在地图掉落上完全一致**，不需要再细分，本工具统一按「限时活动」处理。
- 活动结束后这张图会转成**档案**：游戏里它就是**没有**代币商店、**没有**掉落UP。
  所以打开档案图看到「掉落列表第 0 槽没有代币卡」「金色头像没有 UP 绿标」是**正常状态**，
  不是工具漏读数据 —— 档案模式下这两种提示一律不出现，也不提供「标记污染」按钮。
- **地图数据一律按「限时活动」版本记录**（`token` 保留、金色掉落 `up: true`）。
  模式是页面上的一个开关，切到「档案」时工具把代币和掉落加成直接忽略掉，
  不需要为同一张图再存一份档案版数据。
- 注意这个开关是**全局**的：把档案图切到「限时活动」，工具也会照下面的公式算出一个代币数，
  而那个数在游戏里并不存在（档案没有代币商店）。要看真实状态，就按这张图当前的实际形态选。

### 一轮代币收益

限时活动模式下，「油耗与弹药」里会多出一行**一轮代币**，紧挨着一倍/三倍一轮油耗，两者同处对照：

```
B = BOSS 点数量, N = 普通战斗点数量（起点、补给点这类非战斗点不给代币）
一轮代币 = 90 × B + 40 × N
```

- 代币只跟路线**经过哪些节点**有关，跟编队、出战分配、一倍/三倍都无关（三倍只放大油耗和掉落）。
- `90` / `40` 是**当前认为值**，可能随后修正；数值集中在 `app/oil.js` 的 `TOKEN_REWARD`，改那一处即可。
- 底部「路线对比」表在活动模式下也会多一列「代币」，口径相同。

**为什么非要分这两种模式**：只做一种的话，档案图会一直挂着「非UP」「没有代币」这类提示，
看起来像数据缺了或者图有问题；反过来，活动图不算代币又丢掉了规划时最关心的那个收益数字。
把模式显式化之后，两种图各自显示自己真实的样子，而且同一套页面、同一份数据就能覆盖。

## 覆盖规划（解锁自动作战）

地图上**全部战斗节点都走过一遍（非灰）才解锁自动作战**。底部面板的「覆盖规划」页签就是干这个的：用最少总战数把还没通过的战斗节点走一遍。

**为什么不能只给一条路线**：一次出击只能走一条从起点出发的路线，而图有分支——更硬的是 **O（驱逐≥4）和 Q（驱逐<4）是互斥分支，一趟里物理上不可能同时走到**。所以这是"多趟的集合覆盖"问题，求解用位掩码 DP。

实测本图（博览会的奇妙相遇 / 地狱EX，18 个战斗节点）：

| 场景 | 趟数 | 总战数 |
|---|---|---|
| 全未通过，不允许撤退 | 4 | 28 |
| 全未通过，**允许撤退** | 4 | **25** |
| 已通过 A B E H L P S（示例进度），允许撤退 | 3 | **20** |

`tools/test_core.js` 里用暴力枚举交叉验证过这些数字。

**怎么标"已通过"**：两种都行。

- 手动：在地图节点下方的按钮条里点节点名切换；或者在地图上 **Shift+点击** 节点
- **自动：把游戏地图截图直接拖进页面**。按每个节点记录在数据里的坐标采样图标环上的像素来判定——已通过＝战斗点青蓝 / BOSS 红 / 补给点亮绿，未通过一律灰白。已在真实游戏截图上验证过判定正确

已通过的节点在地图上会画淡，**还需要覆盖的节点左上角有橙点**，一眼能看出还差哪几个。

**选项**：

- `允许中途撤退` —— 开启后候选路线包含所有前缀，最后一趟可能不用走到底，最优解通常更省（本图 28 → 25）
- `包含 BOSS 点` —— 覆盖目标是否含 BOSS（本图两种都是 28 战，因为到深层节点必须穿过 BOSS）
- `用当前编队过滤条件` —— 开启后，带路条件明确不满足的路线不参与规划，避免规划出走不了的方案。注意**编队没填够时（每队不足 2 个舰灵）会自动跳过过滤**，因为空编队会让"至少 N 个"这类条件恒不满足，那是缺数据而不是条件不成立
- `目标` —— 最少总战数 / 最少趟数

规划结果里**点某一趟那一行**，就能把这一趟放到主视图，直接看它的带路条件、油耗和出战分配（和「路线对比」点行的行为一致）。

## 路线历史

页面会顺手记下你走过的路线，**存在 `local/history.local.js` 这个本机私有文件里**（不进 git，
见 [local/README.md](local/README.md)）。**浏览器里不留**：草稿里那份只是会话内的临时副本，
关闭或刷新页面时就被摘掉了；这个项目本身也从来没有任何网络请求。

**两种来源分开记，每种只保留最新的一条**：

| 来源 | 什么时候记 |
|---|---|
| 手动 | 在地图上**一个一个点节点**走出来（含「撤回一步」） |
| 自动 | 直接点程序配好的路线：**「路线对比」或「覆盖规划」里点某一行** |

- **按地图隔离**：历史挂在地图 id 上，换地图各看各的，互不影响。
- 只有**起点一个节点**的不算路线（例如点「清空路线」之后），不记录 —— 所以手滑清空/撤回到底不会把之前点出来的路线冲掉。
- 地图**左下角**常驻一个小框，显示当前地图的手动、自动两条历史和各自的时间。

### 怎么落到文件里

`file://` 打开的网页**不能直接写磁盘**，所以往 `local/history.local.js` 写只有两条路，在「历史管理」页签顶部操作：

1. **手动导出**（任何浏览器都能用）：点「导出 history.local.js」下载，覆盖到 `local/` 下。
   面板上会显示「本次会话有改动还没写进文件」，提醒你别忘。
2. **绑定目录自动写**（Chrome / Edge，用的是 File System Access API）：点「绑定 local/ 目录（自动保存）」，
   选一次这个 `local/` 目录，之后每次历史变化都自动写文件。目录句柄存在 IndexedDB 里，重开页面还能续用；
   权限不在时会提示「需要重新授权」，点一次「重新绑定」即可。

**没绑定的时候，页面顶端会常驻一条横幅**（Chrome/Edge 且尚未绑定、或绑定过但权限已失效时才出现），
上面直接带「选择 local/ 目录并绑定 / 重新授权」按钮，不用先翻到底部「历史管理」页签去找。
横幅上的「关闭」只让它在**本次会话**不再出现（关前要确认一次），刷新后还会回来 ——
因为不绑定就等于关掉页面就丢历史，不该让人在不自知的情况下把它永久静默掉。
浏览器不支持目录绑定时整条横幅不出现（免得给一个点不动的按钮），继续用上面的「导出」即可。

> **没导出、也没绑定目录就关掉/刷新页面，这次会话新产生的历史会丢** —— 这是"历史不进浏览器"的代价。
> 想省心就绑一次目录。

### 历史管理

底部第三个页签「历史管理」：点了之后**下面这一栏会平滑上移盖住地图**，点回「路线对比 / 覆盖规划」再平滑落回来。
（用 `flex-grow` 过渡做的动画；`display` 不能过渡，所以没用显示/隐藏那套，那样是硬切、很突兀。）

- **以地图为单位**，每张有历史的地图占两行（手动、自动各一行），各自标出**记录时间**。
- 排序按**从老到新**：同一张地图取手动/自动里**较新的那个时间**当排序依据，但两条的时间都照原样标出来，
  所以一眼能看出哪条更新、哪张图更近。
- 「管理」目前是**只看 + 删除**：每条历史有「删除」，每张地图有「清空本图」，都会先弹一次确认框。
  管理列表**刻意不可点**，不在这里载回地图（载回只走地图左下角那个历史框，见上）。

### 把历史载回地图

地图**左下角**那个历史框里，**有记录的那一行可以直接点**，点一下就把那条路线载回主视图
（和点「路线对比」里某一行的效果一致：路线、终点油耗、带路条件判定全部跟着刷新）。
**当前正在走的那条**会在行首标一个金色圆点，一眼能看出现在停在手动还是自动那条上。

- 只有起点一个节点的记录本来就不会进历史，所以框里出现的都是能载回的完整路线。
- 「载回」是**调阅**，不会再写一条历史（否则等于自己覆盖自己），也不动记录时间。
- 框本身**不挡地图点击**：双击打开时框是浮在地图左下角的，所以只给「有记录的那行」开了指针事件，
  空白和没记录的那行都能穿透过去点到地图。

另外有两类**契约测试**值得留着，它们挡住的是已经真实发生过的低级错误：

- **数据 ↔ 求值器**：扫描地图数据里所有条件，断言运算符、`kind`、`key` 都能被求值器识别。
  （曾经因为数据写全角 `≥` 而求值器只认半角 `>=`，导致这类条件恒判"不满足"、区间退化成整个定义域，而旧测试用半角构造条件正好错开没抓到）
- **文件 ↔ 草稿**：`mergeById` 的合并语义（草稿优先、文件补充、墓碑挡删除）。

## 本地预览服务器

页面本身是为**双击 `index.html`（`file://`）**设计的，不需要服务器。如果想用 http 预览：

```bash
python tools/serve.py          # 默认 8765，Ctrl+C 停止
```

比 `python -m http.server` 多一件重要的事：**所有响应带 `Cache-Control: no-store`**。Python 自带的 http.server 只发 `Last-Modified`，Chrome 会据此做启发式缓存——改了 `app/*.js` 之后刷新页面可能仍在用旧文件，报出 `FX.xxx is not a function` 这种假故障，很浪费时间。

从旧服务器切过来时**先按一次 Ctrl+F5 硬刷新**，把之前缓存的脚本清掉；之后靠 `no-store` 就一直是新的了。

## 启动排查

页面启动时会把每个模块登记成「期望全局变量 → 文件」，先检查谁没就位、**动态补载缺失的那些**再启动（实测遇到过极偶发的某个 `<script>` 标签没被执行，每次缺的文件还不一样）。真的加载不了才会在页面中间显示缺了哪些模块。

**样式表也有一道同样的自检**：`app/style.css` 偶发没加载成功时，页面照样能跑、但会**完全没有样式**（白底黑字），
很容易被误判成"样式写错了"。所以启动时会验一次，没生效就重新挂一个 `<link>`
（最多补挂两次，补不上也不拦启动，只在顶部提示条上说一句）。

判断依据分两层，**缺一不可**：

1. 首选看 CSSOM 里有没有解析出规则。**但这只在 http(s) 下可靠** —— `file://` 下读 `cssRules`
   一定抛 `SecurityError`（每个本地文件算独立源），那是"读不到"而不是"没加载上"。
   *这里踩过一次*：最初把抛异常当失败，结果**双击打开 index.html 时样式明明是好的，却一直报
   "样式表没加载成功"，刷新也没用**。
2. 读不到规则就退一步看**样式有没有真的作用到元素上**（`#fx-app` 的 `display:flex` + `flex-direction:column`
   只有 style.css 会设）。这样两种情况正好分得开：本地/跨源已加载 → 属性生效 → 算好；
   同源但真的 404/500 → 属性没生效 → 才算坏。

`<link>` 的 `onerror` 不能用作判据 —— 它在这种场景下并不可靠。

如果打开后是空白页：

1. 看页面中间有没有红字提示，会直接写缺哪个脚本
2. F12 → Console 看具体报错
3. 确认 `index.html` 里的 `script` 标签路径和 `data/`、`app/` 下的文件名一致

注意 `file://` 下 `src` **不能带查询串**（会被当成文件名的一部分而找不到文件），所以防缓存的时间戳只在 http(s) 下加。

## 阵营名注意

阵营名是**匹配游戏带路条件的键**，一个字都不能差。已核对过的高风险写法：

- `凤棲` 是「木 + 妻」，**不是**「凤栖」（木 + 西）——这个字最初读错过，`tools/test_core.js` 里加了断言锁住
- `纳榭尔` 的「榭」是「木 + 射」

另外 `tools/test_core.js` 里有一条测试会**扫描地图数据里所有被引用的阵营、断言它们都能在阵营表里找到**。以后新地图的阵营名写错或写漏，跑一下测试就会报出来。
