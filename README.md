# 拂晓 活动地图规划器

> **读者：人。** 这是给人的入口文档。仓库里给 AI 助手看的入口是 [AGENTS.md](AGENTS.md)。

把《拂晓：胜利之刻》的活动地图建模成数据，在图上**点节点选路线**，自动算出这条路
**带路条件能不能走通、要打几场、油点在第几战后、一倍/三倍油耗和弹药消耗、一轮能拿多少代币**。

> **非官方工具**：与《拂晓：胜利之刻》的开发方 / 发行方无关，纯粹是玩家自用的路线规划辅助，仅供个人参考。
> 游戏名称、阵营名、舰名、掉落信息及地图数据的一切权利归原权利方所有。
> 本仓库**不含**任何账号数据：舰灵库与编队都是空模板；页面本身不发任何网络请求。

## 这个工具解决什么

按重要性排序，**前三件就是它被做出来的理由**：

| # | 要做的事 | 在页面哪里 |
|---|---|---|
| 1 | **选路线** —— 在地图上把想走的那条路点出来 | 左侧地图 |
| 2 | **看带路条件** —— 逐条判定每个岔口能不能过、有没有冲突 | 右侧「路线汇总」 |
| 3 | **覆盖规划** —— 用最少总战数走遍所有战斗节点，解锁自动作战 | 底部「覆盖规划」 |
| 4 | 比较全部路线，看油耗 / 弹药 / 代币 | 底部「路线对比」 |
| 5 | 录舰灵库、建编队（给 1~3 提供数据） | 右侧「舰灵库 / 编队」，见[进阶文档](#四进阶功能子文档) |

## 一、下载并打开

**不用装任何东西：不需要 Node、不需要 Python、不需要服务器、不需要联网。**

1. 打开仓库页面 <https://github.com/deadbushxw/fuxiao-map-planner>
2. 点绿色按钮 **Code → Download ZIP**（会用 git 的话：`git clone https://github.com/deadbushxw/fuxiao-map-planner.git`）
3. 解压到任意目录，**双击里面的 `index.html`** —— 工具就开了

几点说明：

- **建议用 Chrome 或 Edge。** 这两个浏览器支持「绑定 local/ 目录自动保存路线历史」。
  别的浏览器照样能用，只是可能无法绑定目录，历史要手动导出（见 [使用详解](docs/使用详解.md)）。
- 用 `file://` 双击打开是**刻意设计**的：页面全部用经典 `<script>` 标签加载，
  就为了绕开 Chrome 在 `file://` 下对 `fetch` / ES module 的 CORS 拦截。
- 打开后 F12 控制台里若有 `local/ships.local.js` 之类的 **404，是正常的** ——
  那是可选的本机私有数据层，没有这些文件不影响启动。
- 页面**零网络请求**，断网也能用。

双击后是空白页？按 [使用详解](docs/使用详解.md) 里的「启动排查」走一遍（多数是缓存问题）。

## 二、三分钟上手

1. **选地图**：顶部下拉里选一张（例如「博览会的奇妙相遇 / 地狱EX」）
2. **点节点**：在左侧地图上**从起点 START 开始点**。当前「可去」的节点外面有一圈**黄色虚线**
   （半径 40px），**圈内随便点哪都算命中**，不用精确戳到图标上
3. **改路线**：点错了按右上「撤回一步」，或者直接再点一次那个节点；「清空路线」从头来
4. **看结果**：右侧「路线汇总」立刻更新 —— 战斗数、油点在第几战后、一倍/三倍油耗、弹药占用、
   **带路条件逐条判定**
5. **看别的可能**：底部「路线对比」列出这张图的**全部路线**（「博览会的奇妙相遇 / 地狱EX」是 23 条），
   按油耗排序，**点任意一行**就把它载回主视图

> ### 注意：第一次打开必读
> 舰灵库和编队是空的（仓库里只有空模板），所以此刻的带路条件是在**空编队**上判的：
> 数字类条件（如 `舰灵数≥10`）会显示 ✗，均速 / 索敌类会显示 `? 未知`。
> **那是缺数据，不是这条路真的走不通。**
> 选路线、看地图结构、跑覆盖规划都不受影响；想让条件判定准，先按
> [进阶-舰灵库录入](docs/进阶-舰灵库录入.md) 和 [进阶-编队](docs/进阶-编队.md) 把队伍填起来。

界面大致长这样：

```
┌ 顶部：选地图 │ 限时活动/档案 │ 一倍/三倍 │ 撤回一步 │ 清空路线 ┐
├──────────────────────────────┬──────────────────────────────────┤
│                              │ 编队 │ 舰灵库                     │
│  地图（点节点选路线）          │ ────────────────────────────      │
│  · 黄虚线圈 = 可去             │ 路线汇总：战斗数 / 油点 / 油耗 /   │
│  · 橙点 = 还没覆盖的战斗点      │           弹药 / 带路条件逐条判定  │
│                              │ 数据文件：导出 ships.js/fleets.js │
│  ┌ 本图路线历史（手动/自动）    │                                  │
├──┴───────────────────────────┴──────────────────────────────────┤
│ 底部：路线对比 │ 覆盖规划 │ 历史管理                              │
└──────────────────────────────────────────────────────────────────┘
```

## 三、核心功能

### 3.1 选路线

地图是一张**有向图**（A→B 则 B 不能回到 A），节点分四类：
`start` 起点 / `battle` 战斗点 / `boss` BOSS 点 / `supply` 补给点（油点）。

- 从起点开始，**下一步可去的节点会亮起黄虚线圈**，在圈内点一下就把路线延伸过去
- 点错两种改法：右上「撤回一步」退一格；或者**再点一次刚才那个节点**原地撤销
- 只有起点一个节点时，右侧汇总不给出结论，也不记历史（所以清空 / 撤回到底不会把之前的记录冲掉）
- 换地图时路线互不影响，每张图各自记自己的当前路线

### 3.2 看带路条件

每个岔口（地图数据里的 `next[].cond`）都带一条**单谓词**条件 —— **没有「且」**，
一条岔口只判一条。判定基准是**两个队伍合并**：

| 原文 | 含义 |
|---|---|
| `旗舰为 战列<2` | 两个旗舰中，舰种为战列的数量 < 2 |
| `舰队中 航母 数量<3` | 两队合并的航母总数 < 3 |
| `舰队中<奥鲁加>数量≥4` | 两队合并的奥鲁加籍总数 ≥ 4 |
| `舰队均速值<34` | 两队合并的均速 < 34 |
| `舰灵数量<10` | 两队合并的舰灵总数 < 10 |
| `舰队索敌值≥800` | 两队合并的索敌 ≥ 800 |

「路线汇总」会把这条路经过的每条条件**逐条列出来并标 ✓ / ✗ / ?**，并带上「来源 → 目标」
（例如 `H→L: 舰队中重巡≥3`），一眼知道卡在哪一段。

两个要点：

- **判「未知」而不是「不满足」**：只要有一个舰灵没录航速 / 索敌，均速 / 索敌类条件判为
  `? 未知`，避免把「缺数据」误报成「走不通」
- **冲突检测**：条件是互斥分段的。如果一条路上同时要求 `航母<3` 和 `航母≥3`，
  求交集为空，页面会直接告诉你**这条路物理上走不通**，而不是分别显示两个 ✗

均速 / 索敌的换算假设（都能在编队里手动覆盖，见 [进阶-编队](docs/进阶-编队.md)）：

- 均速值 = 全部舰灵航速的算术平均
- 索敌值 = 全部舰灵索敌值之和

### 3.3 覆盖规划（解锁自动作战）

游戏里**全部战斗节点都走过一遍**才解锁自动作战。底部「覆盖规划」页签就是算这个：
用最少总战数，把所有**还没通过**的战斗节点走一遍。

**为什么不是给一条路线**：一次出击只能走一条从起点出发的路线，而图有分支 ——
更硬的是 **O（驱逐≥4）和 Q（驱逐<4）是互斥分支，一趟里物理上不可能同时走到**。
所以这是「多趟的集合覆盖」问题，求解用位掩码 DP。

以仓库自带的「博览会的奇妙相遇 / 地狱EX」（18 个战斗节点）为例：

| 场景 | 趟数 | 总战数 |
|---|---|---|
| 全未通过，不允许撤退 | 4 | 28 |
| 全未通过，**允许撤退** | 4 | **25** |
| 已通过 A B E H L P S（示例进度），允许撤退 | 3 | **20** |

**怎么标「已通过」**，两种都行：

- **手动**：地图节点下方的按钮条里点节点名切换；或者在地图上 **Shift + 点击** 节点
- **自动**：把游戏地图截图**直接拖进页面**。工具按数据里记录的节点坐标采样图标环上的像素：
  已通过 = 战斗点青蓝 / BOSS 红 / 补给点亮绿，未通过一律灰白

已通过的节点在地图上会画淡，**还需要覆盖的节点左上角有橙点**，一眼看出还差哪几个。

主要选项：`允许中途撤退`（候选包含所有前缀，最优解通常更省）、`包含 BOSS 点`、
`用当前编队过滤条件`（带路条件明确不满足的路线不参与规划）、`目标`（最少总战数 / 最少趟数）。
**点规划结果里某一趟那一行**，就能把它载入主视图看条件 / 油耗 / 出战分配。

> 选项细节、自动识别的判据、边界情况，见 [使用详解](docs/使用详解.md)。

### 3.4 油耗、弹药与代币

- 每个战斗节点从两队里**任选一队**出战；**每队每轮最多打 5 战**（出战一次消耗 1 弹药），全路线最多 10 战
- 油点返还**上一个战斗节点出战队伍**的一半油，向下取整
- 三倍模式：只放大油耗和掉落，**不改变战斗场次，也不改弹药消耗**

```
F = 某一场出战队伍的全部舰灵油耗之和
一倍: 单战消耗 F      油点返还 ⌊F/2⌋      → 一轮净耗 = ΣF    − Σ⌊F/2⌋
三倍: 单战消耗 3F     油点返还 ⌊3F/2⌋     → 一轮净耗 = Σ3F   − Σ⌊3F/2⌋
```

注意三倍是**先乘三再取整**：F=55 时一倍返 27，三倍返 ⌊165/2⌋=82，而不是 27×3=81。
（返还基数取自油点**前面那一战**的出战队伍，所以队伍分配会同时影响消耗和返还。）

**自动分配**穷举 2^(战斗数) 种方案（最多 1024 种），在满足「BOSS 点必须强队」和
「每队 ≤5 战」的前提下，取所选模式油耗最小的那个。

限时活动模式下还会多一行**一轮代币**（`90 × BOSS 数 + 40 × 普通战斗点数`，只跟路线经过哪些节点有关）。
「限时活动 / 档案」两种形态的区别、代币口径、掉落 UP / 污染这些概念，见
[使用详解](docs/使用详解.md) 的「限时活动与档案」。

## 六、常见问题

| 现象 | 原因 / 怎么办 |
|---|---|
| 双击 `index.html` 是空白页 | 页面中间若有红字，直接写了缺哪个脚本；否则 F12 看 Console，见 [使用详解](docs/使用详解.md) 的「启动排查」 |
| 页面完全没有样式（白底黑字） | `app/style.css` 没加载上。启动自检会补挂，补不上会有顶部提示；硬刷新一次多半就好 |
| 报 `FX.xxx is not a function` | 用 http 预览时的缓存问题。用 `python tools/serve.py`（带 `no-store`），或先 Ctrl+F5 硬刷新 |
| 带路条件全是 ✗ | 大概率是编队还空着。先录舰灵 + 编队，见 [进阶-编队](docs/进阶-编队.md) |
| 改了舰灵库，刷新后变回去了 | 界面改动存在浏览器草稿里；换浏览器 / 清缓存会丢。用「导出 ships.js」落成文件 |
| 路线历史不见了 | 历史不留在浏览器。要么手动导出，要么绑定 `local/` 目录自动写，见 [使用详解](docs/使用详解.md) |
| 三倍油耗不是一倍 ×3 | 正常。三倍是**先乘三再取整**，见 3.4 的公式 |
| 想加一张自己的活动地图 | 采集流程在 [tools/README.md](tools/README.md)；数据格式照 `data/maps/bolanhui.js` |
