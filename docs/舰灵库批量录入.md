# 舰灵库批量录入

> **读者：AI 助手。** 本文是给**按步骤执行采集的 AI** 用的流程说明（读图规则、分批、踩过的坑）。
> 人只看「舰灵库怎么录、字段是什么意思」，请读 [进阶-舰灵库录入](进阶-舰灵库录入.md)。

> 从游戏截图批量建立 `data/ships.js` 的工作方法。
> 手工在界面上一个个加船太慢（上百艘的量级），这篇是把"读图 + 分批 + 交叉验证"跑通的流程。
>
> 跟本仓库的关系：舰灵库是**每个人自己的账号数据**，所以仓库里 `data/ships.js` 是空模板。
> 想让自己这份不进 git，写到 `local/ships.local.js`（见 [../local/README.md](../local/README.md)）。

## 一句话目标

把游戏里实际在用的舰灵，逐个录成 `data/ships.js` 里的一个对象，供规划器算油耗、判断带路条件。

## 数据结构

```js
window.FX_SHIPS = [
  { id: "s1", name: "舰名", oil: 30, type: "轻巡", faction: "凤棲", speed: 19, scout: "" },
  // ...
];
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一即可，自增（`s1`、`s2`…） |
| `name` | 是 | 舰名，照游戏显示原样记 |
| `oil` | 是 | 油耗，参与"每场战斗消耗"和油点返还 |
| `type` | 是 | 舰种，**必须逐字等于** `data/shiptypes.js` 里的名称 |
| `faction` | 是 | 国籍，**必须逐字等于** `data/factions.js` 的键名 |
| `speed` | 可选 | 航速，「舰队均速值」条件要用 |
| `scout` | 可选 | 索敌，**建议留空**（原因见下） |

## 数据从哪读

### 首选：船坞 →「属性」视图

游戏里 **船坞 → 右上角把显示方式切到「属性」**，会出现卡片网格。

「属性」下拉里有 **TYPE 1~5 五种样式**，要选 **TYPE 2** 才是带
`装填/机动/命中/索敌/幸运/消耗/航速` 的那种。TYPE 1 是另一套属性
（`血量/体力/炮击/航空/雷击/装甲/对空`），TYPE 4 是装甲类型 + 装备，TYPE 5 是誓约。
顶栏那个「属性」按钮本身点一下是在「数值卡 / 立绘卡」两个大类间切换，要开 TYPE 下拉得点它右边的箭头。

每张卡片的内容（自上而下）：

```
队伍标记              舰名        ← 左上是队伍标记（没进编队的没有），右上是舰名
 装填 217
 机动 552
 命中 644  (+6)                   ← 青色括号是加成，已含在左值里
 索敌 19
 幸运 57   (+37)
 消耗 32                          ← 要的就是这个 → oil
 航速 48.1                        ← 要的就是这个 → speed
```

**一张截图就能拿到 舰名 + 消耗 + 航速**，效率远高于逐艘进详情页（后者大约慢一个数量级）。

注意：

- `消耗` 是整数，`航速` **可能带小数**（如 `48.1`），照实记
- 卡片左上角有一个很淡的舰种水印，但被队伍标记压住，**不可靠，不要依赖它**

**一屏能放多少张取决于模拟器分辨率**：本项目实测 1920×1080 下只完整放得下
7 列 × 2 行 = 14 张（卡片约 399px 高、行距约 424px，可用视口约 906px），第三行只露出舰名。
别按"一屏几十张"估算工作量，**先截一屏数一下**。

### 这个视图不显示舰种和国籍：按舰种逐批采集

用顶部的 **「筛选」** 分批：

1. **先把「锁定」勾上**（如果你习惯锁定在用的船）。船坞里大量未锁定的船是用来给锁定船升星的素材，勾上「锁定」能把它们全部排除，量级立刻降下来
2. **按舰种筛**：各舰种筛一次。这一批里所有卡片都是该舰种，**一次截图就同时拿到了 舰名 + 消耗 + 航速 + 舰种**，不需要再做匹配
3. **按国籍筛**：各国籍筛一次。这批**只读舰名**（精度要求低），再按舰名把国籍合并回主表

舰名是唯一的键，所以第 3 步的合并是可靠的。两条轴各自独立枚举出的船数应当一致——**不一致就说明漏采了**，这是最值钱的一道交叉验证。

### 备选：舰灵详情页（一艘一图）

只有当需要 索敌、或想核对某艘船时才用。布局：

- **左下角**：舰名大字（可能带 `·改` 后缀或舰号括号，见「舰名怎么记」）
- **舰名上方**：舰种与国籍两个标签
- **左上角**：稀有度（如 `SSR`、`R+`）
- **右侧数值面板**（两列，每项「标签 + 白色数值 + 可选青/红加成」）：
  - 左列：血量 / 航空 / 装甲 / 对空 / 命中 / **索敌** / **消耗**
  - 右列：炮击 / 雷击 / 装甲类型 / 装填 / 机动 / 幸运 / **航速**

**一致性抽查**：批量录完后，挑 2～3 艘同时用「属性」视图和详情页各读一遍，确认 `消耗` / `航速` 两个视图给的是同一个数。不一致说明读数规则理解错了，先停下查清楚再继续。

---

## 最容易搞错的一条规则

数值面板里**白色数字才是真实值**。跟在后面的青色（`+`）或红色（`−`）是装备、天赋等带来的加减值，**但已经包含在白字里了**。

所以：

- `消耗 30 −7` → 记 **30**，不是 23
- `索敌 225 +196` → 记 **225**，不是 421

---

## 字段取舍

- **油耗 `oil`**：必填。同一艘船会随**星级、等级**变化，所以**以你当前游戏里显示的白字为准**
- **航速 `speed`**：填。基本不随装备变化，可信
- **索敌 `scout`**：**建议留空**。它随装备大幅变化，记下来很快失效。地图里需要索敌的那条带路条件，可以在编队里填「舰队索敌值」手动覆盖，比逐舰记录更准
- **舰种 / 国籍**：必须逐字一致。阵营名是匹配带路条件的键，一个字都不能差，特别是 `凤棲` 是「木 + 妻」**不是** `凤栖`（木 + 西，AI识别错过）、`纳榭尔` 的「榭」是「木 + 射」。写错会让带路条件静默匹配不上

## 采集方式

### A. 驱动模拟器（推荐，可批量）

模拟器运行时 adb 可直接连。要点：

```bash
export MSYS_NO_PATHCONV=1        # Git Bash 下必须，否则 /sdcard/... 会被转成 Windows 路径而静默失败

"$ADB" devices                    # 确认在线设备
"$ADB" -s emulator-5556 shell input tap X Y
"$ADB" -s emulator-5556 shell screencap -p /sdcard/_cap.png
"$ADB" -s emulator-5556 pull /sdcard/_cap.png "<项目目录>/shots/dock/xxx.png"
"$ADB" -s emulator-5556 shell input keyevent 4      # BACK
```

`$ADB` 的取法见 [../tools/README.md](../tools/README.md)（环境变量 → `ANDROID_HOME` → `PATH`，**不要把绝对路径写进脚本**）。

**优先用带端口的 serial 之外的稳定名**：如果同一个实例同时以 `127.0.0.1:7555` 和 `emulator-5556` 出现，用后者——含冒号的 serial 拼进文件名后会被 Windows 当成 NTFS 备用数据流，导致主文件 0 字节、普通工具打不开。

流程：进舰灵列表 → 逐个进详情页 → 截图存档 → BACK。
**批量循环里要用截图体积或内容判断上一步是否到位**，不要盲目连点——曾因为误判把几十次 BACK 打在了错误的界面上。

更省事的做法是用 `tools/dock.js` 编排（切视图、设筛选、回顶、滚动、出读图长条、合并生成），见 [../tools/README.md](../tools/README.md)。

### B. 自己提供的截图

把各舰灵详情页/属性页截图放进 `shots/`（或直接发图），逐张读图录入。

### 读图技巧

**不要逐张读整屏**。用 `tools/compose_rows.ps1` 只把每张截图里需要的那一条横带裁出来、纵向拼成一张长图，一次读 5～8 张：

```bash
pwsh -File tools/compose_rows.ps1 -Dir "<项目目录>/shots" \
     -Names "dock-01,dock-02,dock-03" -Out "tools/preview/_batch1.png" \
     -X0 0 -X1 1953 -Y0 220 -Y1 660
```

`-X0/-X1/-Y0/-Y1` 填标定出来的区域。

**属性页的读法**：整张截图在 1:1 下数值是可读的，但**数字有读错的风险**，而且一屏只有十几张、
每艘只要 `舰名` 和 `消耗/航速` 两组数——**整图读是浪费**。更省的做法（脚本在 `tools/dock.js`）：

- 每屏只裁 2 条横带：**舰名行**（行顶 +2~48px）和 **消耗+航速行**（行顶 +266~378px），
  纵向拼成一张长条再读。一屏一屏拼起来读，比整图省很多，也不会看漏
- 行顶怎么定位：卡片暗底 + 行距约 424px（**别用固定偏移硬套**，滑动后相位会变）
- 可疑的卡片随时局部放大 2~3 倍复核
- 批量录完必须做**一致性抽查**（见上），能加一条**双轴交叉验证**更好
- 最后跑 `node tools/validate_ships.js` 兜底（能抓出舰种/国籍写错、油耗非法、id 重复）

**用 `pwsh`（PowerShell 7），不要用 `powershell`（5.1）**：5.1 按 GBK 解码 `.ps1` 里的中文注释，会吃掉 `param()` 那一行导致参数绑定全部失效。

## 舰名怎么记

**照游戏显示原样记录，不要自己加工、不要推断。**

- **改造**过的船，名字带 `·改` 后缀（例如 `某舰·改`），照原样记；详情页国籍右边的「改 / REFORM」是个按钮，有这个按钮不代表这个舰灵是改造过的，只代表她可以改造
- **注意：** 详情页左下角的「改名」是个按钮，不是"改过名"的标记 —— 它出现在**每一个**详情页上，不带任何信息
- 带后缀的名字只有两种来源，都照原样记：
  - `·改` = 改造形态
  - `拉菲(DD-459)` 这种带舰号的括号 = **游戏自己**给同名舰加的区别标记

所以：**不要看图标/按钮去推断名字该怎么写，直接读屏幕上那个名字。** 名字是后续合并数据的键，改写会导致匹配不上。

### 同名舰灵

同一艘船可能有多个形态/多张卡。通用规则：

- **先出现的用原名，之后出现的记 `{舰名}{k}`**（`k` = 2, 3, …）
- 编号按**游戏列表里的先后**定，所以会受解锁状态影响：如果某艘同名舰只采到一艘，先确认另一艘是不是没在筛选范围内
- 不想收重复项，就在生成时用 `node tools/build_ships.js --drop-dup=舰名,舰名` 指定要丢掉的舰名

## 范围

船坞里大量**未锁定**的船是用来给锁定船升星的素材。如果你已经在筛选里勾了「锁定」，那么：

**采集范围 = 处于锁定状态的船**，素材船全部排除。这也让工作量比船坞总数小得多。
代价是**误解锁**会造成遗漏：某艘其实在用的船被解锁后就不在筛选范围里了。

## 交付与验收

1. 写 `data/ships.js`（或 `local/ships.local.js`）：`window.FX_SHIPS = [ ... ];`，保留文件头的字段说明注释
2. `node tools/validate_ships.js` —— **0 个错误**才算通过
   （它会检查：舰种是否在枚举里、国籍是否在阵营表里、油耗是否合法、id 是否重复，并打印舰种/国籍分布）
3. `node tools/test_core.js` —— 不应被弄坏
4. 抽样 3 艘，把截图和录入值**逐字**核对一遍，尤其是 舰名 / 舰种 / 国籍

## 不要做的事

- 不要改 `app/` 下的任何文件，也不要碰 `data/maps/`、`data/factions.js`、`data/shiptypes.js`
- 不要记录索敌（除非确实需要）
- 不要为了「看起来整齐」而改写 舰名 / 舰种 / 国籍 的写法
- **尽量不要把 wiki 数据直接当成你游戏内的实际值**（见下）

## 关于 wiki（慎用）

第三方 wiki 疑似只有 **1★1级** 和 **6★90级** 两档数据，而**油耗的具体算法作者未知**
（是否随星级线性变化、是否随等级变化，都不清楚），此处不依靠它们确认油耗。

`消耗` 恰恰是随星级/等级变的那个字段，所以 wiki 值**尽量不要直接当你当前舰船的实际消耗**。
除非你明确要一份"允许有偏差的全量参考库"，否则一律以游戏内截图的白字为准。

## 采集上容易踩的坑

（处理逻辑都在 `tools/dock.js` 里，这里是排查时的对照表）

1. **筛选面板是「全部 + 多选」语义**：点具体项会追加；点「全部」会重置成全部，
   而「全部」被选中时点一个具体项会变成只选那一项。要精确选单项，固定走「点全部 → 点目标」。
   另外**两条轴是叠加的**（`舰种=X ∩ 国籍=Y` 可能把列表清空，看着像"这批没船"），
   切换轴前必须把另一轴复位。
2. **按钮正中央是文字**（白字/深字），单点采样颜色会判错，必须按区域取比例来判定按钮状态。
3. **滚动位移会飘**（实测 300~848px）。一张卡片要被完整读到，行顶必须落在一个约 562px 宽的窗口内；
   某步超过这个窗口又不是行距的整数倍时就会**整排漏掉**。要用小步滑 + 逐步测量，别信"滚一屏"的估算。
4. **测量位移不能用纯 SAD**：行距是周期性的，纯 SAD 会锁到相邻行报出假的位移，凭空多出一行。
   先按两次截图里第一张完整卡片的行顶相位算出余数，只在该余数的少数几个候选里比 SAD。
5. **不要做画布拼接**：接缝正好压在某一行的「消耗」上会把数字切掉。改成每一行都从"把它摆得最好"的那一屏单独取带。
6. **模拟器重连后 serial 会变**，脚本要自动挑一个在线设备，别写死。
7. **回顶手势方向容易记反**——反了会让每批只拿到列表末尾两行，看着像"这批就这么点船"。
   对照一下每批拿到的数量是否合理再往下跑。
