# 进阶 · 舰灵库录入

> **读者：人。** 这是进阶功能，只在你想让**带路条件判定得准**或**油耗算得对**时才需要。
> 只想选路线、看地图结构的话，[README](../README.md) 那三分钟就够用了。
> 想用截图批量建库（给 AI 执行的流程）看 [舰灵库批量录入](舰灵库批量录入.md)。

舰灵库就是「你手上有哪些船」。它给两件事供数据：

1. **算油耗** —— 每场战斗出战队伍的全部舰灵油耗之和（以及油点返还）
2. **判带路条件** —— 两队合并的舰种数量、阵营数量、舰灵数、均速、索敌

**不录也不是不能用**：选路线、看图和覆盖规划都不依赖它；但「路线汇总」里的条件会按空编队算
（数字类显示 ✗、均速/索敌显示 `? 未知`），那是缺数据，不是你走不通。

## 一、手工录入（最快上手）

右侧面板切到「舰灵库」页签 → 添加。字段如下：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识，自动生成，不用手填 |
| `name` | 是 | 舰名，**照游戏显示原样记**（留空会自动命名为 `{舰种}{序号}`，如「驱逐1」） |
| `oil` | 是 | 油耗（整数）。参与「每场战斗消耗」和油点返还 |
| `type` | 是 | 舰种，**必须与 `data/shiptypes.js` 里的名称逐字一致** |
| `faction` | 是 | 国籍 / 阵营，**必须与 `data/factions.js` 里的键名逐字一致** |
| `speed` | 可选 | 航速。「舰队均速值」条件要用；不填则该条件判 `? 未知` 而不是「不满足」 |
| `scout` | 可选 | 索敌值。同上。**建议留空**（见下） |
| `fav` | 可选 | 收藏标记。收藏的船在列表和选船面板里永远置顶，并写进导出的 `ships.js` |

舰灵库面板支持**全库搜索 + 舰种/国籍筛选 + 按舰名/舰种/油耗/航速/最近使用排序**。

### 舰名怎么记

**照游戏显示原样记录，不要自己加工、不要推断。**

- 改造过的船，名字带 `·改` 后缀，照原样记
- 带舰号的括号（如 `拉菲(DD-459)`）是**游戏自己**给同名舰加的区别标记，也照原样记
- **注意：** 详情页左下角的「改名」是个按钮、国籍右边的「改 / REFORM」也是按钮 ——
  **它们出现在每一个详情页上，不带任何信息**，不要看它们去推断名字该怎么写
- 名字是后续合并数据的键，改写会导致匹配不上

### 同名舰灵

同一艘船可能有多个形态 / 多张卡。通用约定：

- **先出现的用原名，之后出现的记 `{舰名}{k}`**（`k` = 2, 3, …），例如第一艘叫 `某舰`、第二艘叫 `某舰2`
- 编号按**游戏列表里的先后**定，所以会受解锁状态影响；如果某艘同名舰只录到一艘，先确认另一艘是不是没在筛选范围内
- 不想收重复项，就在生成时用 `node tools/build_ships.js --drop-dup=舰名,舰名` 指定要丢掉的舰名

### 舰种 / 国籍必须逐字一致

这两个字段是**匹配游戏带路条件的键**，一个字都不能差。已核对过的高风险写法：

- `凤棲` 是「木 + 妻」，**不是**「凤栖」（木 + 西），AI识别错过
- `纳榭尔` 的「榭」是「木 + 射」

`tools/test_core.js` 里有一条测试会**扫描地图数据里所有被引用的阵营、断言都能在阵营表里找到**；
`node tools/validate_ships.js` 会逐字校验舰种 / 国籍。写错的话跑一下就能报出来。

### 索敌为什么建议留空

索敌值随装备大幅变化，记下来很快失效。地图里需要索敌的那条带路条件，
直接在编队里填「舰队索敌值」手动覆盖更准（见 [进阶-编队](进阶-编队.md)）。

> 同理，「舰队均速值」也能手动覆盖；两个覆盖值都会**立刻**影响条件判定和覆盖规划。

## 二、数据怎么存（三层，不用怕丢）

| 层 | 文件 | 说明 |
|---|---|---|
| 文件层 | `data/ships.js` / `data/fleets.js` | 仓库里的**真实文件**，是初始数据。仓库里这两份是**空模板**（舰灵库人人不同，不适合进公共仓库） |
| 私有层 | `local/ships.local.js` / `local/fleets.local.js` | 可选的**本机私有层**，不进 git。`app/main.js` 启动时按需加载，里面的 `FX_SHIPS` / `FX_FLEETS` 会覆盖掉空模板（文件不存在只留一条 404，不影响启动） |
| 草稿层 | `localStorage` | 运行时的草稿：界面上的改动即时保存、刷新不丢 |

**文件层和草稿层是按 id 合并的，不是二选一**：草稿里的改动优先（本机改过的以草稿为准），
文件里新增的条目会补进来，本机删掉的用墓碑挡住、防止被文件里的旧数据「复活」。
所以 `ships.js` 可以在外部批量重新生成，重新打开页面就能看到新船，**不会覆盖掉你的本机编辑**。

## 三、导出 / 导入

页面是 `file://` 打开的，**浏览器不允许网页直接写本地磁盘**，所以落盘靠导出：

1. 界面上改完，点「导出 ships.js」/「导出 fleets.js」下载
2. 把下载的文件覆盖回 `data/` 下的同名文件
3. 刷新页面确认还在

想让自己的舰灵库**不进 git**，就覆盖 `local/ships.local.js` / `local/fleets.local.js` 代替第一步的目标
（注意：导出文件里没有 `window.FX_LOCAL_SHIPS = 1;` 这行标记，要手动补上；
格式与细节见 [local/README.md](../local/README.md)）。

也可以反向：`data/ships.js` 用外部脚本批量生成后直接覆盖，重新打开页面即可看到
（草稿优先，所以不会覆盖本机编辑）。

> 如果浏览器禁用了本地存储，页面右上角会提示，此时**务必用导出保存**。

## 四、批量录入（上百艘的量级）

手工一条条加太慢时，有两条路：

- **截图驱动**：船坞 →「属性」视图，只裁「舰名」和「消耗 / 航速」两条横带，纵向拼长图后一次读多条。
  完整流程、读图规则、分批与交叉验证、踩过的坑，都在 [舰灵库批量录入](舰灵库批量录入.md)（**给 AI 执行的文档**）
  和 [tools/README.md](../tools/README.md)（采集工具链）
- **直接改文件**：按 `data/ships.js` 的格式批量生成后覆盖，再刷新页面

批量录完**一定要校验**：

```bash
node tools/validate_ships.js   # 舰种/国籍是否逐字匹配、油耗是否合法、id 是否重复；空库直接放行
```

### 尽量不要拿 wiki 数据当自己的实际值

第三方 wiki 疑似只有 **1★1级** 和 **6★90级** 两档数据，而**油耗随星级 / 等级变化的算法未知**。
`oil` 恰恰是那个会变的字段，所以 wiki 值不能直接当你当前舰船的实际消耗 ——
除非你明确要一份「允许有偏差的全量参考库」，否则一律以**游戏内截图的白字为准**。
